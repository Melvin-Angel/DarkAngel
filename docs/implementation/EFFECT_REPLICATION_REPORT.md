# Replicated current effect state and persistent cues

9 October 2026, following action-tag checkpoint 69e3b69. M4/M5 remain **In progress**.

The existing protocol-3 WorldSession now carries a separate bounded owner/public effect-state component. A frame identifies the actor, session, world revision, avatar epoch, captured simulation tick and state revision. At most 64 instances include a scoped effect handle, pinned definition UUID/generation, start/end/next-period ticks, suppression and durable source session/network/activation attribution. Captured source power and statistics remain in native authority and never enter this presentation value. EffectDefinition has explicit server/owner/public visibility, default owner; observers receive only public instances. Optional `.daeffect` visibility freezes with the existing attribute/tag/source/CAS closure.

Existing owner correction/public action byte limits are preserved. Effect-state schema 1 has a separate 16,384-byte bound, 896-byte fragment bodies, at most 19 fragments and packets below the existing 1,000-byte limit. Per-peer partial/sending state is bounded to four actors and two audiences. Fragments prepare a whole frame before publication, reject conflicting duplicates, ignore old revision/epoch data and expire incomplete work with explicit resynchronization state. Periodic complete frames recover loss. Effect sending uses at most a quarter of the shared packet budget and rotates fragments among actor/audience pairs. Partial sends pin their frame until completion or lifecycle change; unchanged status sets avoid new sends except keyframes.

Frames are timestamped presentation state, separate from atomic owner motor/resource correction. They never execute damage, modifiers, expiry transactions or old application events in a client world. A prepared EffectPresentation pins native definitions, validates generation, visibility and lifetime/period policy, and preserves its old view on failure. Source destruction does not invalidate captured attribution. Complete empty frames clear removed statuses; a late observer prepares current active lifetimes without replaying past periods.

Optional `.daeffect` cues declare at most four persistent UUID/key bindings. They are logical game cue identities, resolved by a presentation adapter; they are not new VFX renderer assets. Instant effects reject persistent bindings. Current unsuppressed visible instances reconstruct cue state keyed by session, actor, avatar, effect handle and cue UUID. Begin/Update/End changes are bounded to 512 queued entries. Duplicate state emits no repeated cue; refresh updates the same identity; suppression ends its cue while retaining the status timer; resume begins current presentation; expiry/removal ends it. Avatar changes end old cue identities and begin current ones. Queue exhaustion rejects the new candidate and retains prior state and pending changes. Adapters must drain changes; there is no gameplay mutation through this model.
