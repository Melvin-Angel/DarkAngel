## Preferences and ownership policy

Per-user, per-project path under LOCALAPPDATA/DarkAngel/Editor, keyed from normalized absolute source-root path. Layout/ImGui table state, UI scale, per-workspace kit-panel visibility and console severity preferences persist in this increment. Split-size references rescale with DPI as well as text and controls. Camera pose/pivot remain R1 per-scene session state; cross-restart camera retention and per-section/search preferences are explicit remaining work. No scenes, saves, IDs, publication generation or native draft store are changed by preferences. Hidden exercises disable preferences unless DAE_EDITOR_PREFERENCES supplies an isolated test path. Save at normal shutdown and ImGui dirty autosave interval; explicit Save now is available for preference-only changes; I/O failures are shown in Editor settings. Reset clears presentation layout only. Temporary maximization does not overwrite the last docked layout.

## Implemented specialized-workspace and cross-window adoption

Native reference selection still uses the original compatibility/candidate validation and authoritative draft. It now exposes explicit Open/Edit and Reveal in Assets without assigning a different reference. Assets uses the same supported-editor extension list (including Items), supports double-click Open, and adds Items/NPC/Behavior/Mask filters and collapsible selected details. Character/Player/NPC/Animation/Ability have task-specific column/empty-state labels. Character now places presentation controls beside a larger pose preview, switching to Preview/Presentation tabs when narrow; its detailed preview diagnostics are collapsible. Kit composition is opt-in per workspace; history, creation and specialized controls remain available. VFX/Items sidebars are bounded to avoid claiming the primary surface in smaller windows. Audio switches to task tabs below the three-column width. Composer drawing uses shared background/border/text tokens.

Ctrl+S, Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z use the current Scene or shared native history owner. Focused Mask Editor uses native history while Scene retains its owner when a mask is merely open. Text input, active controls/gestures, popups and Play suppress these authoring routes. Game and browsing do not acquire an authoring owner. Audio/VFX retain their specialized per-asset Save buttons and service callbacks; generic authoring shortcuts do not acquire those workspaces. Keyboard navigation is enabled with a visible blue focus cursor. These commands call existing public save/history methods; no second history/draft store is introduced.

At narrow viewport widths, navigation speed/help move into Navigation..., leaving Orbit/Focus/maximize visible. Place has one compact search/category/options row and a scrollable tile list. Fallback ground height and placement help remain reachable in Options; dropping onto collision keeps its previous behavior. This resolves the clipped first tile exposed by the 24% pilot at 150% scale. Outliner retains clipped single selection, adds case-insensitive name/identity search and Frame selection context action; full names and IDs are in tooltips.

## Live previews (Claude Code, 15 October 2026)

The user asked that each tab keep its most important surface in front and that previews prepare themselves and stay visible, so changes show as they are made. Before this increment four previews needed an explicit button: Character (`Prepare preview`), locomotion graph (`Prepare graph preview`), Composer action (`Prepare character preview`) and Effect (`Prepare preview snapshot`); the Player camera preview needed a per-camera checkbox and was unavailable for the built-in rig; VFX showed nothing until an effect was picked.

- Shared `Shell::PreviewRefresh` (`editor_ui.hpp`, `editor_composer.cpp`): a preview whose target differs from what is prepared (new selection, clip or Character) prepares at once; a draft edit prepares again after 0.4 s with no active field, drag or held button. A failed preparation keeps the previous preview, shows the error inline and is not retried until its inputs change. Each preview has a small Refresh button. Play pauses previews (they need the stopped editor) and they resume after Stop.
- Character: a compatible clip is chosen automatically (preferring one named idle) and the pose preview is ready on opening the tab; appearance edits refresh it.
- Animation: the action preview has its own pane beside the timeline when the workspace is wider than 640 logical pixels (narrower windows keep it inline), so it stays visible while blocks are edited. Duration and block edits refresh it. Graph previews prepare on selection and follow graph/Character edits.
- Ability (Effect): the snapshot prepares on selection and follows draft edits while its simulation is untouched (tick 0, nothing applied). Once the author applies or advances, edits no longer reset it; "Restart with current drafts" reloads explicitly. This keeps the frozen-snapshot gates' semantics.
- Player: the camera preview is shown by default, including for the built-in FreeLook/Aim rig, in its own pane beside the configuration when the workspace is wider than 640 logical pixels (inline in the Cameras section when narrower). A camera list chooses which rig camera to view; Close hides it and "Show camera preview" restores it. The built-in rig is one shared `builtin_cameras()` definition.
- Browsers: "Create gameplay asset" and the New Character / New Player / New NPC forms start collapsed, so search and the asset list come first in each browser column.
- Both new side-by-side panes start their table row before choosing a column; the first build without that crashed the Player and Animation tabs (access violation) in a local capture before any gate ran.
- VFX: opening the tab selects the first effect so its preview plays immediately.
- Audio auditions remain explicit: playing sound automatically on tab open would surprise the author.

Scene layout finding (UX-009): the first full run failed `small` (960 x 640) with "Scene viewport is not dominant". Codex's newer `custom-layout` step stores a 245-pixel Outliner, and docked side panels keep pixel widths when a wider saved layout is restored into a smaller window (Outliner 245 + Inspector 263 left the viewport about 47% of 960). `editor_ui.cpp` now scales the Outliner and Inspector columns back whenever together they exceed 42% of the Scene workspace width; layouts within that bound (including the 245-pixel custom split at 1280) are untouched. Failed receipt: `evidence/r2-editor-ux-3a363e1898.json`.

New exercise `--exercise-live-previews` (`exercises/live_previews_exercise.cpp`) opens Character, an action, an effect, a graph and a Player without any Prepare call, edits the action duration and requires the preview to follow, then undoes the edit. `scripts/verify_editor_ux.py --regressions` adds it plus the existing Composer, graph, Effect reset/reprepare/corrected and camera preview gates.
