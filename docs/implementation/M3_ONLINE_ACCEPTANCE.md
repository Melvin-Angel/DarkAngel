# EOS acceptance input and reproduction

The pinned Windows C SDK is acquired at `EOS-SDK-58105819-Release-v1.19.2.1/SDK`. `DarkAngelOnline` is a separate explicit target; Loopback, GNS and ordinary Headless do not call EOS initialization or link its DLL. The SDK boundary test checks a single process lifetime and rejects platform construction without configuration. It does not qualify online login, lobbies, relay or multiplayer.

The missing live input is an Epic product, sandbox and deployment; a public-client ID/secret with a policy permitting Connect, Lobbies and P2P; the chosen external identity provider; and two authorized external identity tokens. This adapter supports Epic ID tokens or Steam session tickets initially. User account creation is explicit after Connect returns a continuance token. No privileged server credential is appropriate here. Do not paste secrets into chat or commit them.

Keep private configuration/token files under `.cache/online` (ignored) or a user-data directory outside the checkout. Configuration fields are `product`, `sandbox`, `deployment`, `client_id`, `public_client_secret`, `cache_directory`, `schema_hash`, `content_hash`, `identity_provider` (`epic_id_token` or `steam_session_ticket`) and optional `allow_create_user` (default false). Each identity should use its own SDK cache directory. Use the same valid 64-character lowercase schema/content fingerprints for the fixture's two peers; product/deployment/policy must match. No sample secret is supplied.

Build the `m3-relwithdebinfo` preset. Start `OnlineProbe PRIVATE_HOST_CONFIG PRIVATE_HOST_TOKEN host`; after login and lobby publication it prints the public lobby ID. Start `OnlineProbe PRIVATE_CLIENT_CONFIG PRIVATE_CLIENT_TOKEN join EXACT_LOBBY_ID` in another process. The client searches compatible lobbies and selects that exact ID; it does not pick a similarly named lobby. It validates the advertised schema/content/protocol and adopts the host's advertised gameplay epoch before opening the shared WorldSession.

The host publishes a server-owned object, moves it and despawns it only after acknowledged baselines. The client must observe creation and movement before accepting the final empty baseline. Both processes report success, leave the lobby and exit. Record the commands with private input paths redacted, SDK/profile/source hashes, exit codes and bounded logs. Repeat with incompatible content and an unauthorized/nonmember peer, login expiry/refresh, a leaving member and reconnect; verify relay behavior on suitable separate networks. Current SDK tick/network/deadline budgets are initial bounded candidates, not measured hardware/network performance claims.

Until those real service checks pass, keep M3 live qualification unverified. The original instruction to keep M4 not started was superseded by explicit authorization to proceed with M4/M5 through Loopback/GNS; see [STATUS](STATUS.md). GNS UDP localhost evidence does not establish physical LAN device qualification, and SDK initialization does not establish EOS online support.
