Native initial Animation Graph runtime checkpoint (8 October 2026)

The native AnimationGraphPlan compiles stable-ID clip, 1D blend and explicit triangle-based 2D locomotion selectors into a frozen dependency order. Typed speed/forward/lateral inputs avoid per-pose reflection. The initial profile permits 32 nodes, depth 16, eight points/eight triangles per blend and four distinct frozen clip instances. Compilation rejects cycles, missing/unreachable/duplicate nodes, incompatible clip skeleton/signature/count, non-loop locomotion clips, non-finite coordinates, unordered 1D points, degenerate/reversed/duplicate/overlapping triangles and exceeded budgets. 1D input clamps to endpoints. 2D uses barycentric weights inside authored counterclockwise triangles and the nearest triangle edge outside the authored domain, with deterministic authored-order tie resolution.

Per-instance tick/normalized-cycle state is separate from shared plans and clips. Weighted reciprocal clip lengths advance one shared locomotion phase at consecutive fixed ticks; every selected clip samples that normalized phase despite different durations. This is normalized-cycle synchronization, not contact-marker alignment or accepted motion quality. Exact single-clip loop boundaries snap floating roundoff to zero. Render-only evaluate does not advance time. Tick evaluation uses bounded stack arrays and no vectors, reflection or graph allocations. Pose descriptors borrow plan-owned immutable clips and must be consumed while the plan/instance remains alive. The existing Ozz RigPose blender owns each instance's sampling buffers. Root-motion ownership remains separate and locomotion is velocity-driven.

Compiled generation includes the caller source digest, typed topology/parameters/points/triangles and frozen clip identity, skeleton signature, archive SHA and clock/root metadata. Reusing the same caller digest for different plans cannot permit cross-plan correction. Restore rejects wrong generation/non-finite or out-of-range phase before mutation. Invalid parameters or a nonconsecutive tick preserve the clock. Replay from an accepted snapshot yields the same phase as the original fixed-tick sequence.
