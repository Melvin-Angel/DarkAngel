# Coordinated new native source preparation/publication

10 October2026 after `e330512`. NativeSourceEdit now has an explicit create flag: new owned paths require an empty previous digest, absent real source and fresh persistent UUID. Private preparation includes all created files in the same bounded snapshot inventory and frozen dependency closure as edits. New files can reference other staged files. Existing native schemas/importers/catalog/CAS remain authoritative; no asset database or dependency added.

Publication verifies the original source inventory and generations, exclusively creates new files under owned paths, writes coordinated sources and registers new asset identities in the same SQLite transaction as product/generation heads. Normal failure restores edited bytes and removes exclusively owned new files before returning. Failed candidates remain retryable; committed candidates are consumed. External files occupying a requested path are preserved. Source snapshot file/byte and native closure limits also apply to creation. Previously published UUIDs cannot be reused as fresh creations.

Recovery journals include created path/UUID/draft hash alongside originals and heads. This is not crash-atomic and not a cross-process multi-file snapshot. Process/power-loss recovery remains manual; a created-path record is not authorization to blindly delete a file without checking ownership/hash and publication state. Empty parent directories may remain after rejected creation. Published-asset deletion is not introduced.
