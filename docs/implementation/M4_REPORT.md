The deterministic fault harness tests 0/2/5/8 ticks of one-way delay, 0/2/5 percent snapshot loss, duplication, jitter and state reordering. It checks actual injected drops, 38-42 corrections over 120 ticks, 2-10 pending commands, no history overflow and correction distance below one metre. Reliable input that arrives after its intended tick expires; this test verifies neutral release and bounded correction, not automatic clock estimation or uninterrupted movement under WAN delay. The two-process harness is deliberately paced at 40 ms wall time per fixed simulation step; it proves independent process integration, not real-time host performance.

Initial settings are candidate values: 1.8/1.0 m capsules, 0.3 m radius, 45 degree slope, 0.35 m step, 0.25 m floor adhesion, 30 m/s² acceleration/braking, 5/2 m/s speeds, 20 m/s² gravity, 7 m/s jump, six-tick coyote/buffer. Root requests cap at 1 m/tick and impulses at 30 m/s. The tests measure behavior against these settings; no target hardware or cross-platform determinism is qualified. Jolt's floating-point configuration remains the pinned port default.

The subsequent actor-history extension captures up to four character identities, epochs, foot poses, velocities and stances in each retained frame. Isolated replay excludes the owner and uses immutable authoritative peer proxies through the same virtual-character collision path. Motor creation/removal changes topology; duplicate identities and overlapping peer spawn/teleport reject. Multi-character replay requires an explicit owner, which OwnerPrediction supplies. Four moving/stationary, standing/crouched traces replay within 2 cm of the original trajectory, and prove that omitting peer collision changes the result. Missing owner history, ambiguous identity, owner epoch changes and actor removal fail atomically. Replay leaves both live actors unchanged. This consumes recorded peer trajectories; it does not simulate coupled rollback or reapply peer pushes. Optimized integration now passes **32/32** and independent GNS movement still passes. Reproduce with `python scripts/verify_actor_history.py`; [receipt](evidence/m4-actors.json) and [focused traces](evidence/m4-actors-focused.log) retain exact provenance separately from earlier receipts.

The dynamic-box extension now distinguishes authoritative, prediction and replay physics worlds. Only authoritative bodies simulate rigid dynamics or accept impulses; prediction/replay use kinematic authoritative proxies and zero motor push strength. The server motor pushes a 50 kg crate with a candidate 1,000 N strength, dynamic speed limits of 30 m/s and 10 rad/s, and a 500 N·s native requested-impulse cap. Captures retain actual linear/angular velocity and a full normalized quaternion. Replay requires completed-tick dynamic history as well as start-of-tick history, resets proxies to recorded results before support refresh, and never simulates coupled rigid-body rollback. Missing post history fails atomically. Repeated 30-command replays agree with the tested server trace within 2 cm and cannot reapply an impulse to the live crate. OwnerPrediction rejects use of an authoritative dynamic world and continues correctly after proxy reconciliation.

Primitive queries now return DarkAngel world/tick/topology/creation-generation and character-epoch qualification, copied points/normals, typed character/sensor flags and authored primitive subshape key zero. No Jolt BodyID/SubShapeID escapes the adapter. Explicit static/kinematic/dynamic/character/sensor layer masks and owner filtering are shared by ray, sphere sweep and overlap. Sensors require both layer and trigger admission. Closest rays sort equal fractions by logical identity; >32 raw hits reject rather than returning a possibly incorrect closest prefix. Tests reject cross-world, recreated-body and teleported-character results. Primitive material is the default key zero; mesh materials/backfaces remain unqualified.

Completed authoritative ticks collect sensor overlaps after all motor contact refreshes, outside Jolt callbacks. Begin/end use stable ownership tokens and creation/epoch-aware pairs; ends precede replacement begins. Tests cover independent overlapping volumes, reentry, sensor removal, same-ID actor replacement, rigid/virtual recipients and a dynamic body that actually sleeps without a false exit. Prediction emits no authoritative sensor events. Undrained events block the next motor/physics tick before mutation. Per-query 32 hits, 128 active pairs and 128 batch events are bounded; overflow publishes no prefix, records a world resynchronization requirement and prevents further simulation. Native source version 2 supports `motion: sensor` through the same cook/authoring decoder.

Additional motor regressions now cover crouched replay under a standing obstruction and unsafe correction rejection before changing pose/stance. Native velocity memory excludes root requests, is projected through bounded actual contact planes, and retains support-relative planar/world vertical semantics. A vertical root pulse leaves no launch velocity; platform jumps inherit horizontal/vertical velocity once, an attached platform stop does not launch, and a ceiling absorbs an upward impulse. Integration passes **35/35**, independent GNS still agrees at x=7.125/sequence 90, and affected checks without animation pass **3/3**. Remaining DAE-006/009 qualification: arbitrary static triangle-mesh collision cooking and material/subshape/backface policies; broader platform scheduling and pitch/roll rotation; network-fed actor/prop proxies, dynamic snapshot replication and coupled-player correction; live streaming barriers/ownership transfer; automatic clock-offset/jitter estimation and input redundancy; detailed allocation/CPU/bandwidth/jitter measurement and production stress. Root requests are native trusted requests, never client-authorized displacement. Full coupled rigid-body rollback, arbitrary local gravity and advanced traversal remain explicitly deferred by the architecture.

M5 may begin against this tested primitive collision profile after the M4 local checkpoint. Its own gates remain independent and must not be marked Verified prematurely. M3 EOS still needs the private deployment/policy and two identities; MCP remains the tested 2025-11-25 compatibility profile.
